# Agile Project Plan

## Product Vision
Create an easy-to-use appointment booking system that reduces manual scheduling and gives customers and providers a clear view of appointments.

## Personas

### Customer
Wants to find a provider, select a time slot, book an appointment, and manage bookings.

### Service Provider
Wants to publish availability, view bookings, and update appointment status.

### Administrator
Wants to oversee users, providers, appointments, and system health.

## Sprint Plan
| Sprint | Goal | Main Deliverable |
|---|---|---|
| Sprint 1 | Planning & Foundation | Requirements, architecture, database, project setup |
| Sprint 2 | Users & Providers | Registration, login, profiles, search, availability |
| Sprint 3 | Appointment Booking | Booking, cancellation, rescheduling, dashboards |
| Sprint 4 | Quality & Release | Unit testing, functional testing, bug fixing, documentation |

## Definition of Done
A task is Done when implementation is complete, acceptance criteria are satisfied, code is reviewed, required tests pass, and documentation is updated.

## Kanban Policy
- Backlog: future work
- To Do: selected for active sprint
- In Progress: actively being developed
- Code Review: implementation ready for review
- Testing: validation in progress
- Done: accepted and verified

## Agile Practices Demonstrated
- User stories
- Acceptance criteria
- Sprint planning
- Kanban flow
- Small increments
- Code review
- Testing
- Retrospective-oriented improvement
