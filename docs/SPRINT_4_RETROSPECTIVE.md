# Sprint 4 Retrospective

## What Went Well
- Requirements were broken into small user stories.
- GitHub Issues provided clear work items.
- Provider search and appointment rescheduling were delivered as incremental features.
- Testing was added for booking, search, cancellation, and rescheduling.

## What Could Be Improved
- Authentication is planned but not yet implemented in the demo build.
- Availability is currently simplified and can be expanded into explicit time-slot records.
- A real multi-member GitHub Project board can be connected to these issues for visual status tracking.

## Action Items
- Add explicit user authentication.
- Add provider-managed time slots.
- Add stronger integration coverage.
- Review the Kanban board weekly and limit work in progress.

## Retrospective Outcome
The team will keep issues small, review acceptance criteria before moving items to Testing, and prioritize quality checks before marking work Done.
